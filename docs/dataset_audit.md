# Dataset Audit & Scope Boundary Report

## 1. Executive Summary
- **Dataset Inspected**: `creditcard.csv` (ULB / Worldline benchmark)
- **Total Record Count**: 284,807 transactions
- **Feature Count**: 31 columns (`Time`, `V1` to `V28`, `Amount`, `Class`)
- **Target Variable**: `Class` (Binary: 0 = Legitimate, 1 = Fraud)
- **Class Balance**: 
  - Legitimate (`Class = 0`): 284,315 (99.8273%)
  - Fraud (`Class = 1`): 492 (0.1727%)
  - Imbalance Ratio: ~578 to 1
- **Temporal Horizon**: 172,792 seconds = exactly 48.00 hours (2.00 days)
- **Missing Values**: 0 nulls across all 31 features
- **Duplicate Records**: 1,081 identical rows

---

## 2. Feature Schema & Distributions

### `Time`
- Elapsed seconds from the initial recorded transaction.
- Non-negative, spanning 0.0 to 172,792.0 seconds.
- Reflects circadian variations in transaction frequency.

### `Amount`
- Transaction monetary value in currency units.
- Minimum: $0.00
- 25th percentile: $5.60
- Median: $22.00
- Mean: $88.35
- 75th percentile: $77.17
- 99th percentile: $1,017.97
- Maximum: $25,691.16
- **Zero-dollar transactions**: Exactly 1,825 transactions have `Amount = 0.00`, of which **27 are confirmed frauds**. In card payment processing, zero-dollar transactions represent card authorization verification checks (account status inquiries) commonly used by fraudsters to test whether stolen credentials are active before making purchases.

### PCA Components `V1` through `V28`
- Generated by ULB / Worldline using Principal Component Analysis to preserve consumer confidentiality and proprietary terminal telemetry.
- Orthogonal linear combinations of original card, user, terminal, and merchant attributes.
- **Top Fraud-Correlated Signals**:
  - Strongly Negative: `V17` (-0.326), `V14` (-0.303), `V12` (-0.261), `V10` (-0.217)
  - Strongly Positive: `V11` (+0.155), `V4` (+0.133), `V2` (+0.091)

## 3. Dataset Suitability & Architectural Boundary Assessment

### Classification: **SUITABLE FOR TRANSACTION RISK INTELLIGENCE WITH CLEAR BOUNDARIES**

#### What the Dataset Genuinely Supports:
1. **Severe Class Imbalance**: Real-world 0.17% fraud rate requires asymmetric loss functions (`scale_pos_weight=578`), non-linear tree splits, and validation threshold calibration.
2. **Temporal Validation**: Sequential 48-hour event stream mandates strict chronological 70/15/15 train/validation/test splitting to prevent future lookahead leakage.
3. **Behavioral & Statistical Deviations**: Right-skewed amounts, $0 authorization flags, and PCA risk polarities provide strong signal for supervised trees and unsupervised anomaly detectors (Isolation Forest).

#### Architectural Boundary (What the Dataset Does NOT Support):
1. **Absence of Entity Identifiers**:
   - The dataset contains **NO** `account_id`, `card_id`, `customer_id`, `device_id`, `ip_address`, or `merchant_id`.
   - **Honest Engineering Reality**: Without entity identifiers, true entity-level fraud ring detection, device farm analysis, or customer-specific velocity cannot be discovered from this dataset.
   - **Architectural Extension**: In a production enterprise bank setting with relational event logs (e.g., Device Fingerprint SDK, IP Geo-location, Card Tokenization), the pipeline naturally extends by adding entity-level bipartite graphs. We document this clearly as a future architectural capability rather than fabricating synthetic entities.
